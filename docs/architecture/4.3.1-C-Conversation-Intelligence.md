# 4.3.1-C — Conversation Intelligence Architecture

## Pipeline

HTTP chat request
→ conversation history retrieval
→ ConversationIntelligence analysis
→ ContextAssembler
→ model/deterministic response route
→ context trace + diagnostics

## State

`ConversationState` contains:

- `current_objective`
- `current_task`
- `current_deliverable`
- `resolved_request`
- `references`

The state is explicit so continuity decisions can be inspected instead of being hidden inside prompt text.

## Reference Resolution

Resolution is deliberately conservative. It operates on the available conversation history and only expands short conversational references when a usable prior target exists. It does not invent missing context.

Examples covered by the build:

- `Change that`
- `Use PostgreSQL`
- `Do it again`
- `Use the same design`
- `Use the previous version`
- `it`
- `that`
- `this`
- `those`
- `previous design`
- `last build`
- `current project`

## Continuity Rule

If a reference cannot be resolved from available history, the original request is preserved rather than fabricated into a different request.
