# 4.3.1-D Evidence & Confidence Architecture

## Pipeline

```text
User Request
     ↓
Conversation History
     ↓
ConversationIntelligence
     ↓
Knowledge Retrieval / Evidence
     ↓
EvidenceConfidence
     ↓
ContextAssembler
     ↓
Model Context
```

## Confidence Semantics

| Level | Meaning |
|---|---|
| High | Multiple relevant sources provide strong retrieved support with no detected conflict. |
| Medium | Relevant retrieved support exists but is limited in breadth or corroboration. |
| Low | Evidence is weak or conflicts were detected. |
| Unknown | No supporting evidence was available. |

These levels describe **evidence coverage**, not objective truth probability.

## Evidence Measurements

- `evidence_count`: number of evidence items supplied to the evaluator.
- `source_count`: number of distinct source identifiers.
- `conflicts_detected`: conservative contradiction flags requiring review.
- `support_strength`: `strong`, `partial`, `weak`, `conflicted`, or `none`.

## Response Structure Guidance

When the response contains evidence-bearing claims, the model is instructed to distinguish:

1. **Facts** — claims supported by supplied evidence.
2. **Open Questions** — material gaps, uncertainty, or conflicts.
3. **Recommendations** — clearly labeled suggestions rather than established facts.

## Important Limitation

Conflict detection is intentionally conservative and heuristic. It is a review signal, not a semantic theorem prover. A detected conflict must be surfaced rather than silently resolved.
