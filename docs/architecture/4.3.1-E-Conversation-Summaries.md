# 4.3.1-E Conversation Summaries Architecture

```text
SQLite messages (complete transcript)
          |
          v
ConversationSummaryService
          |
          v
conversation_summaries (derived state)
          |
          +------> ContextAssembler
          |            |
          |            +--> summary
          |            +--> recent messages
          |            +--> existing context/evidence
          v
        model
```

The transcript is never replaced by its summary. Summaries are derived state and can be refreshed from the original messages.

### Refresh policy
- Below 100 messages: no summary is required.
- At 100+ messages: create a summary when none exists.
- Refresh after 50 additional messages.

### Inspection
`GET /api/context/summary?conversation_id=<id>` returns the stored derived summary record.
