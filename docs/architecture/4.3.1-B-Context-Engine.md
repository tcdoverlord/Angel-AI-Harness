# 4.3.1-B Context Engine

## Before

The chat handler directly assembled the system prompt, date context, capability report, knowledge context, and conversation history before dispatching to Ollama.

## After

```text
/api/chat
   ↓
request / conversation / lane resolution
   ↓
ConversationStore → recent history
   ↓
ContextAssembler
   ├─ system rules
   ├─ current objective
   ├─ current request
   ├─ project context (if resolved)
   ├─ relevant knowledge (if found)
   ├─ evidence (if verified input exists)
   ├─ tool results (if verified input exists)
   └─ recent conversation
   ↓
context trace + diagnostics
   ↓
Ollama request / deterministic application route
```

## Context trace

Each assembled context records:

- model identifier
- ordered context blocks
- per-block token estimates
- history count and limit
- truncation decisions
- exact prepared model messages

The trace is local application data and is intended for engineering inspection. It is not a new persistence authority.

## Storage boundary

Conversation storage remains SQLite through `ConversationStore`. The context engine reads the already-authoritative conversation history and does not alter the database schema.
